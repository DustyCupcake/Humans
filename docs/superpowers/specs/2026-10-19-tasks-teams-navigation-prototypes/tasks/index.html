Tasks — UI prototypes

Static, fake-data mock-ups of the Tasks and Teams on tasks specs. They load Humans’ real tokens.css and site.css, so the look is the app’s own; only the components in _proto.css are new proposals. Nothing is wired up.

Team page

Changes with involvement: switch Visitor / Contributor / Holder / Coordinator in the bar. Tasks as List, Board and Timeline; contact point; next meeting with a scheduling poll; milestone timeline with both reporting layers; coordinator staffing panel.

Task page

Slots (hands on the work vs learning alongside), status, dates that follow the production calendar, dependencies, subtasks, checklist, notes / comments / activity, the access the task grants, and the coordinator’s staffing controls.

Spec: Tasks
Get involved

Org-wide open tasks, ranked by urgency then fit. Featured band, filters, “My tasks”. Tick I hold the curate task in the bar to see featuring and the needs-attention queue.

Spec: Tasks
Production view

Phase spine, reporting by team, overdue, teams without coordination, and a switch for the team-reporting layer.

Spec: Tasks · production calendar
What is new versus Humans’ existing look
  • Reused as-is: navbar, cards, buttons, badges, breadcrumb, list groups, alerts, forms, Font Awesome icons.
  • New components (in _proto.css): avatars, criticality and status pills, slot dots, task rows, milestone list, status steps, board, gantt-lite timeline, production matrix and phase spine, poll cells.
  • Not designed yet: mobile polish, empty states, the Concerns screens, notifications, drag-and-drop behaviour, the proposals queue, the Calendar tab, localization.

The team and task pages use the page actions on phones pattern (header actions, at-a-glance cards first, sticky action bar); compare with today's layout side by side in the phone comparison.

The top bar on these pages predates the navigation proposal: Get involved and Production are meant to live inside its group menus, not as extra top-level links.
